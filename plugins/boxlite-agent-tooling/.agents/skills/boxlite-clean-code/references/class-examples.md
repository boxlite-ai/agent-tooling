## TL;DR
Split responsibilities when they change independently, while preserving cohesive state, observable behavior, and useful local simplicity.

## How it works
The examples are original sketches rather than replacement libraries. Name the concrete change pressure, establish its contract, and extract in small verified steps. Class count and line count are diagnostic hints, not objectives.

## C01 — A small dashboard can still own unrelated responsibilities

```python
@dataclass(frozen=True)
class ReleaseVersion:
    major: int
    minor: int
    build: int


class FocusTracker:
    def __init__(self):
        self.current_component = None
```

A dashboard exposing many controls is an obvious candidate for inspection. Even one exposing only focus methods and version methods still combines UI interaction with release identity. Separate those owners; the dashboard can receive both when it genuinely presents both.

**Check:** a release-version change does not require altering focus logic, and a focus change leaves release identity alone. Preserve public forwarding accessors while supported callers migrate. A short name or a one-sentence description does not by itself prove a good boundary.

## C02 — Stack operations belong with stack state

```python
class IntegerStack:
    def __init__(self):
        self._items = []

    def push(self, item):
        self._items.append(item)

    def pop(self):
        if not self._items:
            raise EmptyStack()
        return self._items.pop()

    def size(self):
        return len(self._items)
```

Push, pop, and size describe one coherent abstraction. The adaptation derives size instead of maintaining a second counter. A method need not touch every field to belong to the class; maximizing a field-access metric can introduce unnecessary coupling.

**Check:** empty pop has the specified error, values come out last-in-first-out, and size follows every operation. This is not a concurrent stack contract; making individual methods thread-safe would not automatically make caller check-then-pop safe.

## C03 — Do not hide temporary state just to shorten argument lists

```python
def render_document(source, margins, typeface, output):
    layout = PageLayout(source, margins, typeface)
    layout.write_to(output)
```

Before, extracting steps from a long function tempts you to move its locals into a long-lived service's fields. After, a per-call object can own a cohesive layout calculation, or the helpers can simply keep explicit arguments. The new object earns its place only if its operations and state form a useful whole.

**Check:** successive calls cannot reuse the previous document's state; nested calls remain valid; resource ownership and output order are unchanged. Do not add a helper object merely because a function has four parameters.

## C04 — Separate prime generation, page layout, and invocation

```python
def write_prime_report(count, output):
    primes = generate_primes(count)
    printer = NumberPagePrinter(rows=4, columns=3, field_width=6)
    printer.write(primes, output)
```

Before, one function interleaves candidate testing, page counters, and output. After, invocation chooses the count/output, generation owns the algorithm, and the printer owns layout. Extract existing mechanics first; replacing the prime algorithm at the same time prevents a clean comparison.

```python
def test_prime_report_preserves_layout():
    output = io.StringIO()
    write_prime_report(13, output)
    assert output.getvalue() == APPROVED_THIRTEEN_PRIME_REPORT
```

The fixed expected report is independently reviewed, not regenerated by the printer. Separate generator tests verify known prime values. Use invocation-local generation state; copying static mutable arrays into a reusable service changes concurrency and reentrancy behavior.

**Check:** initial primes, page/column order, partial last page, spacing, headings, and page breaks. Define whether zero or negative counts are allowed before testing new support; adding that support is a behavior change.

## C05 — Localize statement changes when SQL generation actually grows

```python
class SelectAccounts:
    def build(self, account_id):
        return ("SELECT id, balance FROM accounts WHERE id = ?", (account_id,))


class UpdateAccountBalance:
    def build(self, account_id, balance):
        return ("UPDATE accounts SET balance = ? WHERE id = ?", (balance, account_id))
```

Before, one generator mixes create/select/insert details and grows whenever any statement changes. Focused generators can localize a new update operation. Common fragments should have one owner when they enforce the same rule; composition or functions can be simpler than a subclass per statement.

**Check:** existing statements and parameter order remain compatible when update support is added. Values remain bound parameters; dynamic identifiers require their own validation. A stable, complete generator need not be decomposed for a speculative future statement.

## C06 — Fix quote inputs to test portfolio arithmetic

```python
class Portfolio:
    def __init__(self, quote):
        self._quote = quote
        self._holdings = {}

    def add(self, symbol, shares):
        self._holdings[symbol] = self._holdings.get(symbol, 0) + shares

    def value(self):
        return sum(shares * self._quote(symbol)
                   for symbol, shares in self._holdings.items())


def test_portfolio_uses_current_quotes():
    prices = {"ACME": Decimal("12.50")}
    portfolio = Portfolio(prices.__getitem__)
    portfolio.add("ACME", 4)
    assert portfolio.value() == Decimal("50.00")
```

Before, a test depends on a live exchange changing prices. After, a callable supplies deterministic prices while the portfolio performs the real calculation. A protocol/interface is also appropriate when the dependency has a richer contract.

**Check:** multiple holdings, repeated additions, unavailable prices, and currency rules as required. The arithmetic test proves nothing about real exchange authentication, units, or response conversion; test the production quote adapter separately.
